### Git Branch Organisation

To organise our collaborative work, each team member used a separate Git branch for their contribution.

| Branch             | Contributor | Purpose     |
| ------------------ | ----------- | ----------- |
| `zoe-2.1`          | Zoé         | Statistical tests (Q/A) – Section 2.1 |
| `Elouan-branch`    | Elouan      | PrePost data analysis – Section 2.2 |
| `Tuba-section-2.3` | Tuba        | Snoring dataset analysis – Section 2.3 | 

Each branch was used to develop and commit individual contributions. Once the work was ready, a Pull Request was created to review and integrate the changes into the `main` branch. The `main` branch contains the integrated group report and the corresponding PDF.

## Team Workflow and Git Strategy

We used Git and GitHub to organise our collaborative work and manage changes to the project. Our workflow included:

1. Creating a shared public GitHub repository.
2. Cloning the repository locally to work on the project.
3. Creating separate branches for individual contributions.
4. Working on separate files to avoid modifying the same document simultaneously.
5. Committing changes with meaningful commit messages.
6. Pushing branches to GitHub.
7. Creating Pull Requests to review and integrate contributions into the `main` branch.
8. Updating the main report and rendering the final PDF.
